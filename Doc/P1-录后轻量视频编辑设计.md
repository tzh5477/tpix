## 1. 现状（以代码为准）

```
ToolVideo::saveFile()       停录 → win->stopRecord() → 空路径则直接 close
                            → Util::getSaveFilePath() 弹保存框 → CopyFile → DeleteFile(temp) → close
ToolVideo::finishRecord(剪贴板) 停录 → Util::addFileToClipboard(temp) → close（temp 留给剪切板）
CapVideo::stop()            卸钩子 → 藏遮罩 → MustEnd → join 采集线程 → 返回 temp.mp4 / temp.gif
                            帧数为 0 时删文件返回空串
CapVideo::startMp4()        DXGI 桌面复制 → VideoMp4::DesktopCapture()（内部 IMFSinkWriter）
                            编码器 HEVC → H.264 逐个回退；宽高对齐 4/2
```

三个前提事实（决定了路线）：

1. **产物位置**：`Setting::getDataPath() + L"temp.mp4"` / `temp.gif`，编辑期间由我们独占。
2. **`VideoMp4.hpp` 只有"采集→编码"一条路**：`CAPTURE` + `DesktopCapture()` + `IMFSinkWriter`，
   **没有任何读回 / 解码 / 解析能力**（已全文确认）。
3. **产物是标准 MP4**（MF muxer 写的），所以系统解码器一定读得回来 —— 这是选 MF 转码的前提。

## 2. 范围分期

| 期 | 内容 | 状态 |
| --- | --- | --- |
| **P1-a** | 编辑窗 + 头尾裁剪 + 导出/复制/丢弃 + 预览播放 | 本期做 |
| P1-b | 画幅裁剪 / 等比缩放（导出分辨率与录制不同） | 预留（转码管线里加一层 `MFVideoProcessor` 即可，接口先留好） |
| P1-c | 区域放大标注（某时间区间内放大某块区域，教程刚需） | 建议 P2 —— 要"随时间变化的变换"，是每帧变换 + 关键帧插值，成本远高于前两项 |
| — | GIF | **不做编辑**。GIF 是自己的编码器、8bit 调色板，改帧要重做量化与调色板；且 GIF 上限 6 分钟、定位是"小片段"，编辑价值低 |

## 3. 技术路线

### 3.1 为什么不走"无损关键帧裁剪"

- 无损裁剪 = 只保留部分样本、重写 `moov/stbl` 索引、时间戳平移。**必须自研 MP4 box 解析 + 重写**，
  而 tpix 的 mp4 是 MF muxer 产出（`VideoMp4.hpp` 无解析器），等于新引入一个脆弱组件。
- 精度受 GOP 限制：H.264 硬编 GOP 常在 1–2 秒，裁不到用户拖的那个位置，观感就是"剪不准"。
- 收益只有"不重编码"，但 1080p 硬编转码通常快于实时，用户等 1~2 秒无感。

### 3.2 选定的管线（MF 转码）

```
temp.mp4 ──IMFSourceReader──┬─ 视频：解码 → (可选 VideoProcessor 缩放/裁画幅) → NV12/RGB32
                            └─ 音频：解码 → PCM（重采样到编码器要求的格式）
                                   ↓
                      时间过滤（pts < in 丢；pts > out 停）
                                   ↓
                    IMFSinkWriter ── H.264/HEVC（硬编优先）+ AAC ──→ 新 mp4
```

要点：

- **裁剪**：`IMFSourceReader::SetCurrentPosition(in - 余量)` 先 seek（MF 自动落到关键帧），
  然后**丢弃 pts < in 的样本、pts > out 后停止**。因为整段重编码，精度就是帧级，与 GOP 无关。
- **音频对齐**：视频/音频各按自己的 pts 裁；AAC 帧长 1024 样本（~23ms），起止各允许半帧误差。
  导出后校验 `|视频时长 - 音频时长| < 1 帧` —— 这是最容易出错、必须进验收的一条。
- **编码参数继承录制**：分辨率、fps、码率（`vbrm=2 / vbrq=50 / Qu=50`）照搬 `startMp4` 的取值；
  `MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS` 打开，硬编不可用时 MF 自动回退软编（慢，但可用）。
- **HEVC → H.264 回退**：复用 `CapVideo::startMp4` 里那套"targets 逐个试 / 编码器逐个试"的写法，
  逻辑同源（可抽成一个共用函数，但**不要**为省事把录制路径也重构成转码路径）。

### 3.3 预览：与导出共用同一条解码链

- 预览**不是**另找一个播放器控件，而是"按当前时间点向解码器要一帧，画到自绘画布上"，
  播放态由 `Ling` 定时器（33ms）推进 —— 与导出用的是同一套解码配置，**所见即所得**。
- 画布复用 `WinHistory.cpp` 里 `CoverImage` 那套（`Ling::Canvas` 子类 + `ID2D1Bitmap1`），
  两处差异：
  1. 编辑预览用 **contain**（整帧可见，便于看裁剪点），不是 cover；
  2. **位图只建一次、逐帧 `CopyFromMemory`**（每帧 `CreateBitmap` 等于每帧 8MB 分配 + 拷贝，
     1080p 下会明显掉帧）。
- ⚠️ 画布后端：预览画布窗口尺寸固定，可用默认 `CompositionDrawingSurface`；**一旦要支持
  "随窗口缩放重排"就得 `enableSwapChain()`**（默认后端尺寸一变内容即清空，见 TOPIC-ling-ui §11）。

## 5. 关键实现决定（后人别改）

1. **预览与导出共用解码参数**：两处各写一遍迟早会分叉成"预览对、导出错"。
2. **编辑期间不删临时文件**：`CapVideo::stop()` 返回路径后所有权归编辑窗；只有"导出成功 / 丢弃 /
   重新录制"三条路会删它。
3. **不倒放**：MF `SourceReader` 无反向解码。逐帧后退 = seek 到目标时间再解到目标帧，代价 O(GOP)。
   拖动播放头要**节流**（同 `WinAiChat` 流式重画的 33ms 节流思路），否则拖动时把解码器拖死。
4. **转码线程**：与 `CapVideo` 同款 `std::jthread` + 进度回调（进度用 `IMFSinkWriter` 的
   `MF_SINK_WRITER` 编码时间 / 总时长估算），UI 侧只更新一个进度条。
5. **失败要给话**：转码失败（解码器缺失 / 硬编失败且软编也失败）必须弹提示（复用
   `CapVideo.cpp` 里 `showRecordError` 的形态），**不能**静默收场 —— "录完什么都没有"是历史雷区。

## 8. 风险与验收

| 风险 | 对策 |
| --- | --- |
| 硬编不可用 ⇒ 软编慢 | 进度条 + 可取消；>2 分钟的视频给"预计耗时"提示 |
| 音视频不同步 | 起止各自裁 + 导出后校验时长差 < 1 帧 |
| 拖动播放头卡顿 | 节流 + 拖动期间降采样解码（每 N 帧解一帧） |
| 长视频（上限 120min）内存 | 全程流式，不整段读进内存；预览只保留当前帧 |

**验收（探针可自动化的部分）**：造一段 5 秒 30fps 的录制 → 裁掉头 2 秒、尾 1 秒 → 导出 →
① 时长 ≈ 2.0s（±1 帧）；② 首帧内容等于原视频第 60 帧（拿截图比对）；③ 音视频时长差 < 1 帧；
④ 编辑窗关闭后临时文件仍在，丢弃后文件消失。

### 9.3 踩坑清单（都已在代码注释里标了原因）

1. **🔴 `MFCreateSourceReaderFromURL` 直接返回 `E_INVALIDARG(0x80070057)`** —— 同时把
   `MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING` 与 `MF_SOURCE_READER_ENABLE_VIDEO_PROCESSING`
   设进属性表就会失败；只开 `VIDEO_PROCESSING` 又喂不出 RGB32（`SetCurrentMediaType` →
   `MF_E_INVALIDMEDIATYPE 0xC00D36B4`）。**只有只开 `ADVANCED`** 才能既建成功又出 RGB32。
   定位办法：写了个 `diag` 命令把 8 种属性组合穷举一遍。
2. **每个窗口都得自己 `show()`** —— `createNativeWindow` 不带 `WS_VISIBLE`（`WinBase.cpp:180`）。
   漏了的症状是"第一次点编辑没反应、第二次才有窗口"。
3. **剪切板里的产物被 `onDestroy` 删掉** —— `Util::addFileToClipboard` 只把**路径**放进 `CF_HDROP`，
   不复制文件，而剪切板那条路走 `closeWindow()` → `onDestroy` 无差别删 `tmpOut` ⇒ 剪贴板里躺着一条
   死路径。加 `tmpToClipboard` 标记，`onDestroy` 里 `if (!tmpToClipboard)` 才删。
4. **语言键必须写成嵌套对象** —— 12 个键起初写成 `video` 段里的**扁平键**（`"title"`/`"start"`…），
   而 `Lang::get` 按 `.` 切段逐级下钻，`video.edit.title` 要求 `video.edit` 是个**对象**，
   扁平写法取不到、**不报错**，界面上直接把键名画出来。顺手把工具条的提示键从 `video.edit` 改名
   **`video.editTip`**（`video.edit` 整段让给裁剪窗那组文案）。
5. **几何单位混用** —— `trackGeom()` 里 `kSide` 是**逻辑**像素，`timeline->w` 是**物理**像素
   （`Node` 的 setter 已乘过 dpi）。直接写 `kSide` 在 125% 缩放下左右各差 4px，画的轨道、手柄和
   `msOfX/xOfMs` 的命中会一起偏。改成 `const float side = kSide * dpi;`。
6. **到 `outT` 后只能停对应那一路** —— 视频与音频必须各记各的 `vDone/aDone`，两路都到才 `break`；
   否则会按先到的那一路把另一路也截断。
7. **HEVC 装不上换 H.264 之前要 `wr.Reset()`** —— 否则 `IMFSinkWriter` 上残留的流配置会让重试继续失败。
8. **交错读取只能用 `ReadSample(MF_SOURCE_READER_ANY_STREAM, ...)` 一趟走**（MP4 的索引要求交错）；
   `GetNativeMediaType` 只能按**流的真实索引**查 ⇒ 得自己先 `findStreams()`。

### 9.4 🔴 验收口径修正（重要）

§8 第③条"音视频时长差 < 1 帧"**对 tpix 自己的录制产物不成立**，实测源片本身就不齐：

```
源片 container=9169.8ms  video=7666.6ms/230帧  audio=9169.8ms/173帧
```

原因在录制侧：`VideoMp4.hpp` 的 `ThisDurV = frameDuration.count()` 是**墙钟步长**，而 DXGI 桌面复制
**只在画面变化时吐帧** ⇒ 静止桌面录出来的**视频轨比音频轨（= 容器）短一截**。所以"拿源片容器时长
当基准去要求音视频对齐"是拿一把错的尺子。

**修正后的判据**（探针实际采用）：

| # | 判据 | 阈值 |
| --- | --- | --- |
| ① | 输出**视频轨**时长 ≈ 应用真实区间（`out - in`） | ±1.5 帧（50ms @30fps） |
| ② | 输出视频轨**样本数** ≈ 区间 × fps | 同上 |
| ③ | 输出**音频轨**时长 ≈ 应用真实区间 | 报告实测值，不作为硬门槛 |
| ④ | 输出首帧内容 = 源片 `in` 处那一帧 | mean\|Δ\| < 对照帧的一半 |
| ⑤ | 关窗保留 temp；丢弃/导出成功才删 | 布尔 |

另：**目标区间必须落在视频轨内部**。源片视频轨只有 7.7s 而容器 9.2s，若按容器时长取 out，
"裁"出来的后半段根本没有画面 —— 转码会老老实实地在视频轨耗尽处停下（实测：in=130 / out=7786 →
输出视频 4400ms = 5533−130）。这不是 bug，是拿容器当尺子的后果。探针现在按
`out_target = min(4500, max(in+1000, vid_ms-400))` 选点。

### 9.6 探针与校验器（都在 `D:\tmp\tpixp1\`，**不进仓库**）

- `harness/trimchk.cpp` + `build-chk.ps1` —— 命令行校验器，链接主构建的 `VideoTrim.obj` + `pch.obj`
  （`/Yu`/`/Fp` 必须与主构建一字不差，且**必须带 `pch.obj` 否则 LNK2011**）。子命令
  `probe / diag / seq / trim / dump`；`dump` 写出裸 `.bgra`（自定格式：4 字节 w + 4 字节 h + 紧密 BGRA）。
  本机没有 ffmpeg / pyav，这个校验器同时充当"帧级比对工具"。
- `probe4.py` —— GUI 验收探针（4 条 cycle）。**三条硬约束**：① 录制工具条挂了
  `WDA_EXCLUDEFROMCAPTURE`（`CapVideo.cpp:136`）⇒ **不能用截图定位录屏工具条**，一律按几何算；
  ② `--enter=video` 是"框完之后直奔录屏条"，不是"启动即录屏"；③ `Node::setBorder` 不进 yoga 布局
  ⇒ 工具条子节点从 `x=0` 起排。
- `cycler.py` —— 被摄物（置顶窗口，色相每 33ms 转 137°）：既保证桌面持续变化（DXGI 才吐帧），
  又让不同时刻的颜色可区分，首帧比对才有意义。
- `mp4info.py` —— 裸解析 MP4 box，逐轨时长 / 样本数。
- ⚠️ 被摄物是 `-topmost` 而编辑窗**不置顶** ⇒ 它会把编辑窗的鼠标点击全吃掉（键盘按焦点派发不受影响，
  所以「Ctrl+C / ESC 好使、按钮没反应」，极具迷惑性）。**进编辑窗前必须先杀掉它**。
- ⚠️ 连着重启同一个 exe 时，**DXGI 桌面复制偶发拿不到**（`DuplicateOutput` 失败 →
  `CapVideo.cpp:236` 弹「系统提示」），表现为 `temp.mp4` 0 字节 + 一个"录制没开始"的弹框。
  探针侧对策：进程间多等 2~3s，并在点「开始录制」后**按 `temp.mp4` 是否长个子确认**（`ensure_recording`），
  失败则关弹框重试 —— 工具条变宽**不能**当成功判据（失败时它照样切成录制形态）。
