# 标注选中与工具条布局改造方案

两项需求：① 选区工具条去掉「更多」折叠、四个功能按钮竖排到选区右侧；② 修复标注消失与样式不生效两个 bug。

---

## 一、需求 1：工具条布局改造

### 现状

`ToolCap` 是一个双行窗口：第一行 = 4 个功能按钮（长截图 / 录屏 / 文字识别 / 二维码）+ 主行标注工具 + 「更多」分隔线；第二行（`rowExtra`）折叠放非默认标注工具与 4 个动作按钮，靠 `setExpanded` 展开。

### 目标

- 长截图、录屏、文字识别、二维码识别 → **选区右边缘外，竖排**
- 其余 13 个按钮（9 个标注工具 + 图像标记 / 保存 / 剪贴板 / 关闭）→ **选区下方横排**
- **彻底删除「更多」折叠**：`rowExtra`、`btnMore`、`expanded`、`setExpanded`、`computeRowCounts`、`defaultShapeIds` 及其 `getToolFlag(L"toolCap", …)` 筛选一并清掉

### 架构

「右侧」与「下方」是两个不同位置，一个窗口只能是一个矩形 → **拆成两个独立窗口**。

```
WinCap（宿主）
 ├─ ToolCapStage  新增：选区右边缘外竖排 4 个 stage 按钮
 └─ ToolCap       改造：选区下方横排 13 个 shape + action 按钮
```

`WinCap` 新增成员 `std::unique_ptr<ToolCapStage> toolCapStage`，在原本操作 `toolCap` 的每一处成对处理。

### 定位规则

新增 `WinCap::layoutToolSide(Ling::WinBase* tool)`，算法参考 `CapLong::layoutTool`（`CapLong.cpp:471-487`）：

| 项 | 规则 |
|---|---|
| 水平 | 默认 `maskRect.right` 外侧 `+ strokeWidth + 2*dpi`；右侧放不下（`win->w - maskRect.right - 2*dpi < toolW`）则换到左侧 |
| 垂直 | 与选区顶部对齐；贴到工作区顶/底则夹住 |
| 兜底 | 不越出所在显示器工作区（复用 `MonitorFromRect` + `GetMonitorInfo`） |
| 下条 | `layoutTool` 保持现状（选区下方右对齐 + 上下翻转 + 夹屏） |

### 窗口细节

- `ToolCapStage`：`body->setFlexDirection(Column)`，宽 `btnSize(32)`、高 `btnSize * 4`；样式、DPI 事件、`Tip`、`onKeyDown` 转发 `WinCap` 均照抄 `ToolCap`
- `ToolCap`：单行 `rowMain`，`shapeBtns`(9) + 分隔线 + `actionBtns`(4)，宽 `btnSize * 13 + spliterW`
- 码位与 `Lang` key 全部复用现成，不新增
- `--enter=long|video|ocr|qr` 旁路不经过按钮，不受影响
- 登记新文件进 `tpix.vcxproj`

### 需同步成对处理的 `WinCap` 调用点

`relayoutTool`、选区变化的两次 `layoutTool(toolCap.get())`、`onClosed` 的 `close()`、两处 `hide()`、topmost 的 `SetWindowPos`。

## 二、需求 2a：点空白处标注消失

### 根因（已验证）

`History.cpp:138-145`，`shapes.erase(it)` 与 `return` 写在 `if` 外、`for` 体内 → **第一轮无条件删掉 `shapes[0]`**。

触发链：点空白 → `onMove` 清 `shapeHover` → `onDown` 新建临时 shape → `onUp` 判定「按下没拖」无效，调 `removeShape` → 误删上一笔标注，临时 shape 留在图上。

### 修复

`erase` / `refresh` / `return` 移回 `if` 内，并顺带清 `selected`：

```cpp
void History::removeShape(ShapeBase* target)
{
    for (auto it = shapes.begin(); it != shapes.end(); ++it) {
        if (it->get() == target) {
            canvas->shapeHover = nullptr;
            canvas->selected   = nullptr;
            shapes.erase(it);
            canvas->refresh();
            return;
        }
    }
}
```

修复后点空白的完整行为：清 `selected` → `onDown` 新建临时 shape → `onUp` 判空 → 正确删掉**这个临时的** → **标注保留，选中取消**。

## 三、需求 2b：选中丢失导致样式不生效

### 根因（两层，相互独立）

1. **没有持久选中态** —— `WinPin::onMove` 移出标注即把 `shapeHover` 置空，「选中」随鼠标一起没了，往工具条的移动过程中必然丢失
2. **样式链路只认编辑态** —— `WinPin::onToolStyleChanged` 只调 `editingShape->applyStyle()`；`ShapeBase::applyStyle()` 是空实现，矩形族（Rect/Ellipse/Line/Arrow）从没 override，颜色是构造时的快照

### 方案：分离 hover 与 selected

`Canvas` 新增字段 `ShapeBase* selected{ nullptr }`：

| 事件 | `shapeHover` | `selected` |
|---|---|---|
| 鼠标移到某标注上 | = 它 | 不变 |
| 鼠标移到空白处 | = `nullptr` | **不变** |
| 点击某标注 | = 它 | = **它** |
| 点击空白处 | = `nullptr` | = `nullptr` |
| 画完一笔（`onUp` 保留） | 保持 | = **新画的这一个** |
| 删除 / undo 命中 | 清 | 若指向它则清 |
| 关窗、切缩略图、换底图 | 清 | 清 |

**Delete 键**：`History::removeHoverShape` → `removeActiveShape`，`target = selected ?: hover`。

### 视觉区分（已定：方案 A）

- hover → 空心手柄（现状保留，提示「这里可以拖动」）
- selected → 空心手柄 + **实心填充**

在 4 个类的 `paintDragger` 里加一行，判断复用现有 `win->selected` 指针（**不新增字段**，零冗余）：

```cpp
ctx->DrawRectangle(dragger, brushDragger.Get(), win->getDpi());
if (win->selected == this) ctx->FillRectangle(dragger, brushDragger.Get());
```

覆盖 `ShapeRectBase` / `ShapeLineBase` / `ShapeArrow` / `ShapeNumber`。`ShapeText` 已对旋转手柄做实心、`ShapeWatermark` 手柄是全屏框（填充会盖图）→ 均不改。

`WinPin::paint` 改为 hover 与 selected 都画手柄（两者不同时各画一次）。

### 样式链路

`WinPin::onToolStyleChanged`：

```cpp
void WinPin::onToolStyleChanged()
{
    auto target = editingShape ? editingShape : drawing->selected;
    if (target) target->applyStyle();
    refresh();
}
```

为取工具条样式的各 shape 补 `applyStyle()` override（构造里怎么取，这里就重取一遍）：

| 类 | 重取的字段 |
|---|---|
| `ShapeRect` | `brush` 色 + `strokeWidth` + `isFill`(取 `isRectFill`) |
| `ShapeEllipse` | `brush` 色 + `strokeWidth` + `isFill`(取 `isEllipseFill`) |
| `ShapeLine` | `brush` 色（含半透明）+ `strokeWidth` |
| `ShapeArrow` | `brush` 色 + `arrowSize` + `isFill`(取 `isArrowFill`) |
| `ShapeMosaicRect/Line`、`ShapeEraserRect/Line` | 仅 `strokeWidth`（占位色固定，不取工具色） |
| `ShapeWatermark` | 调 `makeLayout()`（它本就从工具条取字号/颜色） |
| `ShapeNumber` / `ShapeText` | 已有，不动 |

### 「应用到全部」按钮

- 位置：`ToolSub` 中能改样式的 9 个 `show*Tools`（rect/ellipse/arrow/line/text/number/mosaic/eraser/watermark），`initSlider` / `initColorBtns` 之后各加一行；`showPinTools` 不加
- 外观：**短文本 `L"全"`**，走 `makeTextToggle` 同款非图标字体设置（图标字体里没有「全」以外更贴切的码位，硬猜会显示方块）；提示 key `tool.applyAll`
- 语义：**只作用于当前工具同类的标注** —— `ToolSub` 的颜色是每工具各存一份，跨类型应用会让文字/序号被矩形的颜色污染
- 实现：`ShapeBase` 加公有成员 `std::wstring toolId`，`History::createShape` 建完统一赋值（`result->toolId = curId`）；`WinPin::applyStyleToAllShapes()` 遍历非 undo 且 `toolId == curId` 的 shape 调 `applyStyle()` 后 `refresh()`
- `Lang` 新增 `tool.applyAll`

## 五、折线画完之后单击选不中（2026-10-10 修复）

现象（作者原话）：**「折线画完之后虽然标记点已经聚焦折线但还是无法单击选中，每次单击就变成新的折线起点了」**。

根因：`ShapeLine::mouseDown` 的折线分支（`isPoly()`）**无条件**走「落节点」那一支，
完全不看 `hoverDraggerIndex`。而 `WinPin::onDown` 在「按在已有元素上」时会把这次按下
直接转给那个元素（`shapeHover->mouseDown()`），于是压在**已经画好的**折线身上那一下：

1. `linePoints.assign(1, {x, y})` —— 已经定形的那条折线当场被打回「一个节点」；
2. `building = true` —— 顺带挂上「正在画」；
3. 之后每一次点击都被 `WinPin::buildingShape()`（从后往前找第一个 `isBuilding()` 为真的元素）
   接走接着续画，**再也回不到「选中」**。

修复：给折线分支加一条与 `ShapeLineBase::mouseDown`「首次创建」**完全一致**的判据
（`hoverDraggerIndex == -1`，且 `linePoints` 为空），只有「刚落下的这一笔」才在这里落节点。
落在已有折线上的分两种：

| 命中态 | 含义 | 处置 |
|---|---|---|
| 0 / 1 | 首端 / 末端夹点 | 下沉给 `ShapeLineBase::mouseDown`，拖动交给 `mouseDrag` 接管 |
| 8 | `hitTest` 给的「整条平移」 | 同上 |
| 其它（没算出来） | —— | **直接 return** |

最后那条「直接 return」是必要的：交给基类反而会走进它的「首次创建」分支
（它判的就是 `hoverDraggerIndex == -1`，而这时 `hoverDraggerIndex` 未必是 -1），
往折线尾巴上补一个点。抬手照旧建立单选（`WinPin::onUp`），「单击 = 选中」自然成立。

验证（A/B 单变量：把工作区的 `ShapeLine.cpp` 换回 HEAD 编一个对照 exe，其余改动留着，
两次跑同一份探针 `D:\tmp\tpixp1\probe_poly.py`）：

## 六、工具条「选中工具」的底色改为主题色实底（2026-10-10）

作者反馈：主题色已经实时生效了，但**工具条上那枚选中工具的背景还是灰的**，
换哪一档主题色都不动。

### 根因（两层，只有第二层是本轮改的）

1. **`Setting::getThemeSoft()` 算出来的根本不是"浅染"，是一块与主题色无关的脏灰。**
   `0xFF + static_cast<int>((v - 0xFF) * 0.10)` 里的 `v` 声明成 `const unsigned int`
   ⇒ `v - 0xFF` 在 `v < 255` 时按**无符号回绕**成约 42 亿，`static_cast<int>` 越界（UB）。
   拿真编译器跑（`cl /O2`）：

   | theme | `getThemeSoft()` 实得（原样打印） | 落到底色 |
   |---|---|---|
   | `0x1677FF` | `0x9B9B8BFF` | rgb(155,139,255) |
   | `0x13C2C2` | `0x9B9B9A92` | rgb(155,154,146) |
   | `0xF5222D` | `0x9B9F9A83` | rgb(159,154,131) |

   最后一行的 rgb(155,154,146) 与作者截图里那块灰**逐像素一致**。
   `getThemeSoft()` 全工程共 **9 处**调用（工具条选中格、子工具条开关、历史窗 tab、
   AI 气泡、下拉选中项、录制档位、导出按钮…），所以它们**统统**是那块灰 —— 修一处全好。
   修法：`v` 先转 `double` 再算（`255 + (v-255)*0.1` 恒为正，`+0.5` 后截断即四舍五入）。
2. 把工具条选中态从「浅染」改成「**实底**」—— 作者要的是"与主题色一致"。
   与设置页左侧菜单选中项、开关「开」态同一套：铺满 `Setting::getThemeColor()`，字形翻白。

### 改法

- `ToolMain::applySelectStyle()`（新）/ `applyNormalStyle()`：底色 + **字色**成对上。
  `Ling::Button::setColor` 是**粘的**，选中翻白之后不复位，取消选中那一枚会一直是白图标
  —— 压在白色工具条上等于没了。
- `ToolMain::paintIcons()`：从 `layout()` 里抽出来。「选择对象」「选文」那两枚**不写字**，
  图标是 `Canvas` 上自绘的，`setColor` 管不到 ⇒ 选中态翻白只能重画。两枚各有自己的判据
  （`curId == "selector"` / `win->getTextSelect()`），后者是两态开关、状态住在 `WinPin` 里。
- `ToolSub::applyToggleStyle()`：子工具条的矩形 / 圆形类别、填充等开关，同款实底 + 白墨。
