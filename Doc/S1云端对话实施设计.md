## 2. 配置：`ai` 组

存储位置沿用现有机制（`%appdata%\tpix\config.json`，或便携模式下 exe 同目录的那一份）。

| 键 | 含义 |
|---|---|
| `ai.baseUrl` | OpenAI 兼容服务地址，**手工填写**。形如 `https://api.deepseek.com/v1` |
| `ai.apiKey` | 密钥，**手工填写** |
| `ai.model` | 当前选中的模型。**下拉选或直接输入都能写**，服务层只当它是个字符串 |
| `ai.models` | 上次拉下来的模型列表，填下拉框用。没拉过就是空数组 |
| `ai.historySave` | 是否落盘对话历史，默认开 |
| `ai.historyLimit` | 最多保留几个会话，默认 50（夹到 `[1,500]`） |
| `ai.historyDays` | 保留最近多少天，默认 30（夹到 `[1,3650]`） |

**API Key 明文落盘** —— 这是刻意的，理由：本机单人工具，现有的「导出配置」功能会被加密反向劣化（换台机器导入就废了）；真正的风险补偿是 **`exportConfig` 跳过 `apiKey`**，与已有「`pin` 不导出」是同一条规矩：搬不到别处的东西就不搬。若要改成加密，代价是导出功能需要额外保留一份明文——**待您确认是否接受明文**。

**地址容错**：用户粘进来的可能是服务根，也可能是完整 endpoint。`baseRoot/chatEndpoint/modelsEndpoint` 三个helper各自处理了这两种形态（去尾斜杠 + 按需补路径），不做别的魔法。

## 2.1 对话历史落盘（`AiHistory`）

**为什么单独一个文件，而不是塞进 `config.json`**：`config.json` 会被「导出配置」整个带走，聊天记录跟着配置去别的机器不合适；而且对话是随时追加的，`config.json` 是任何一项设置改动都整体重写的，让它跟着频繁重写不划算。

存储与读写**照抄 `ShotHistory`**：`init/dispose/get` 静态单例、目录建在 `Setting::getDataPath()/ai/`、进程启动时 `load()` 一次、之后每次增删整体 `save()` 回写、UTF-16LE（用 `Ling::Util::saveFile` / `readFileText` 这一对）。

| 成员 | 说明 |
|---|---|
| `create()` | 开一个空会话，返回 id（毫秒时间戳，撞了往后顺一位）。**刻意不写盘**：开了却一句话没说就关掉，不该在历史里留一条空的 |
| `append(id, msg)` | 追加一条消息。首条 user 消息顺带定标题（换行压成空格、截断 40 字）。内容为空直接忽略 |
| `remove(id)` / `clear()` | 删一条 / 全清（连文件一起删） |
| `list()` | 时间新的在前（内部按升序存，返回时反转） |
| `find(id)` | 只读地取一个会话 |

**清理策略（`trim()`，写盘前必跑）**：两个维度各管一段 —— 先按 `historyDays` 丢过期的，再按 `historyLimit` 从最旧那条开始删。两条都留着是因为它们防的不是一回事：**天天聊的人会被条数卡住，偶尔聊的人会被天数清掉**。`load()` 里也跑一遍：配置可能在关掉程序这段时间里被改小了。

**关掉「保存对话历史」是动真格的**：`append()` 直接不记，`load()` 不读，`save()` 把已有文件删掉 —— 磁盘上不留聊天记录；切换那个开关时 UI 还会再调一次 `clear()`。

**「模型」这一行的两条路**：下拉按钮填的是上次 `验证` 拉到的列表（存在 `ai.models`），旁边的输入框可以直接打任何模型名。下拉选完**只往框里填**，落盘统一由 `onTextChanged` 那一支做 —— 两条路共用一个出口，免得哪天走到不同的键上。列表还是空的时候点下拉，提示先做一次连接验证，而不是弹一个空列表。

## 3. 服务层接口（`AiService`）

```cpp
static bool ready();                          // 三项配置齐全与否
static TaskPtr models(onModels, onDone);      // GET /models：既是下拉框数据源，也是「连接可用」的判据
static TaskPtr chat(msgs, onDelta, onDone);   // POST /chat/completions，stream=true
```

**`models` 与「验证连接可用」是同一个请求。** OpenAI 兼容接口没有专门的 ping 端点，`/models` 能返回列表就说明地址、密钥、网络三者都通。所以设置页上的「验证」按钮不需要单独的接口——拿到列表就显示 ✓ + 模型数，失败就显示错误文案。

**Task 的取消语义**：
- `cancel()` 之后**不再回调片段**（`postDelta` 里查标志位），但**收尾回调照送一次**（`postDone` 不查）——UI 靠它解锁输入框，不必自己区分是成功了还是被取消的；
- 析构**不自动取消**：这是刻意的约束。迟到的回调会打到已析构的窗口上，**窗口销毁前必须由调用方 `cancel()`**（语义类似 `WinOcr::onDestroy` 里那份保护）。

**线程模型**（照抄 `Update.cpp` 的既有范式）：
`co_await winrt::resume_background()` 把网络扔到后台线程，回调一律 `Ling::App::get()->dq.TryEnqueue` 回 UI 线程。所有回调都走 TryEnqueue —— 包括"配置没填"这种根本没发请求的失败，保证 UI 一定先拿到 `TaskPtr` 再被调用，不会出现「回调比赋值回来还早」的经典 bug。

**超时是两段的**：
| 阶段 | 阈值 | 手段 |
|---|---|---|
| 连接 + 等响应头 | 15 s | `ThreadPoolTimer` 到点 `Cancel()` 那个 async op（`Update.cpp` 同款） |
| 流已开、两次数据之间 | 30 s | 每次 `ReadAsync` 单独挂一个 idle 定时器 |

只做单段超时是不够的：连接之后服务器吊着不发数据，会让请求永远挂着、回调再也不来。

**SSE 解析**：`pending` 缓冲区按 `\n\n` 切事件，没凑齐的字节留下等下一次；`stream` 收尾不带换行的情况靠循环后补一次 `drainEvents`。字节是按原始字节存的，所以**半个 UTF-8 字符跨分包不会乱**（只有在按字符处理时才会出问题）。同时兼容 `delta.content`（流式）与 `message.content`（非流式网关）。

### 3.1 编译期踩到的坑（已修，留档）

| 现象 | 根因 |
|---|---|
| `req.Headers().Append(...)` 报 **C3779**（"要使用将会返回 auto 的函数，必须首先定义此函数"） | 少了 `#include <winrt/Windows.Web.Http.Headers.h>`。`Append` 的返回类型由这个头文件给出，只带 `Windows.Web.Http.h` 编译器看不到声明 |
| `choices.GetObjectAt(0, nullptr)` 报 **C2660**（函数不接受 2 个参数） | `IJsonArray::GetObjectAt` 只收下标，**而且是"不是对象就抛"**，不能靠传 nullptr 兜底。改为 `GetAt(0)` + 先查 `ValueType() == JsonValueType::Object` |
| `e.code() == hresult_canceled()` 报 **C2678** | winrt 没给 `hresult` 与 `hresult_canceled` 定义 `==`。改为比 `e.code().value == HRESULT_FROM_WIN32(ERROR_CANCELLED)` |
| `resp.Content().ReadAsStringAsync()` 给 `parseModels` 报 **C2664** | 协程返回的是 `winrt::hstring`，不是 `std::wstring`。显式包一层 `std::wstring{ ... }` |

## 3.1 图片通道（表格截图提取）

`AiService::Msg` 多了 `image / imgW / imgH`（BGRA top-down，与 `Util` 同一套格式）。序列化时走
OpenAI 兼容的 `image_url` 通道：

```json
{"role":"user","content":[
  {"type":"text","text":"把这张表提出来"},
  {"type":"image_url","image_url":{"url":"data:image/png;base64,…"}}
]}
```

- **PNG → base64 都在服务层里做**：`Util::encodeImageBytes`（新增，WIC 编到 `SHCreateMemStream`
  的内存流里，不落临时文件）+ `CryptographicBuffer::EncodeToBase64String`（`windowsapp.lib` 已链）。
  纯文本那条路仍给字符串，不为带不带图分两套代码。
- **图不落历史**：一张满屏截图 base64 之后几 MB，全塞进 `history.json` 会把文件撑到看不懂。
  所以重开一个旧会话时那张图不在 —— 这是刻意的取舍。
- 图在 `msgs` 里**留着**：多轮对话时模型得一直"看得见"它，代价是每轮重编一次 base64（几十毫秒）。

**取图路径**：对话窗上的「粘贴图片」读剪贴板（`Util::readClipboard`）。tpix 截完图默认就在剪贴板上，
所以"截一张表 → 打开 AI 对话 → 粘贴 → 提问"是通的，不需要另接截图管道。

## 4. 对话窗（`WinAiChat`，已完成）

- 左侧 180 宽：**「新对话」+ 会话列表**（`AiHistory::list()`）。列表**最多 12 条且不套 ScrollerBox** ——
  滚动容器里的可点控件命中坐标要减滚动量（WinSetting 里那套 `shiftForScroll` 补偿），
  十几条历史犯不上引入那套逻辑。更老的靠清理策略自己走。
- 右侧：消息区（`ScrollerBox` + 一列 `Ling::Label` 气泡，**非交互，所以不受上面那个命中问题影响**）
  + 输入区（`TextBox` 多行 + 发送 / 停止 + 粘贴图片）。
- **每次都把整个会话的 messages 全发出去**：兼容接口是无状态的，想让它记得前面说过什么只有这一条路。
- 流式：delta 追加到同一个气泡，收尾（`onDone`）才把整条写进历史。`onDestroy` 里 `cancel()` + `alive` 标记双保险。

**未做**：回车发送（`Ling::TextBox` 只暴露 `onTextChanged` / `onFocusChanged`，没有 `onKey`）、
单条会话的手工删除、Markdown 渲染（A5）。

### 4.1 热键 `Alt+I`（选中内容 → 对话）

取词与翻译那条路共用 `Util::copyFromForeground()`（发 `Ctrl+C`、读剪贴板、还原剪贴板，
细节见 `Doc/S2S3翻译实施设计.md` 3.1 节）。

与翻译唯一的不同：**只填进输入框，不替用户按发送**。对话是要花钱的，而且十有八九还要
再加一句"用表格总结"之类的要求。若日后要改成自动发送，改 `WinAiChat::onCreated` 末尾那段即可。

**对话窗必须遵守的两条**（服务层的既有语义推出来的）：
- 发一条就 `AiHistory::append` 两条（user 提问、assistant 完整回答），**回答流式走完再落盘**，别每个 delta 都写一次文件；
- `onDestroy` 里 `task->cancel()`：迟到的回调会打到已析构的窗口上。注意 `postDone` 是「取消也照送」的，光 cancel 挡不住它 —— 所以设置页那个验证按钮另外用了一个 `shared_ptr<bool>` 存活标记，对话窗要同款处理。
