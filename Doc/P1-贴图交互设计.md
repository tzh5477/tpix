# P1-1 贴图交互打磨 · 设计（含与「侧边栏贴图隐藏」的结合）

> 目标：把 Snipaste 那种"贴图质感"补进 tpix，**且不与现有的书签条隐藏机制打架**。  
> 本文只谈**需求与交互**；每处都标了落地锚点（源码位置），供实施时对照。  
> 现状核对基于本仓库 `Src/`（`WinPin` / `PinHiddenBar` / `ToolMain` / `ToolSub`）。

---

## 1. 现状：一张贴图"收起来"其实已经有 4 种形态

| 形态        | 状态量                            | 收成什么样                         | 在哪                    | 怎么还原            |
| --------- | ------------------------------ | ----------------------------- | --------------------- | --------------- |
| 缩略图       | `WinPin::isThumb`              | 窗口缩到 ≤160×120（`setThumbMode`） | **原地**                | 图上点一下           |
| 贴边细条      | `WinPin::isMinimized`          | 窗口收成一条贴屏幕边的细条                 | **原屏幕边**              | 悬停展开（Ctrl+M）    |
| **藏进书签条** | `WinPin::isHidden` + `barEdge` | 窗口**完全隐藏**，在屏幕左上角那条彩色书签条里占一格  | 屏幕左上角（`PinHiddenBar`） | 悬停 peek / 拖着拖出来 |
| 关闭        | `isClosed`                     | 窗口销毁                          | —                     | 不可逆（从未撤销）       |

> 结论：**"隐藏"这条线已经做好了——缺的不是机制，是"交互密度"。**

## 2. 书签条（`PinHiddenBar`）当前的三个缺口

通读 `PinHiddenBar.cpp` 后，这条书签条的全部交互只有两条：

- **hover 一格 → 整窗 peek**（`reveal`：把那张贴图整张显出来贴在线右边，离开 800ms 收回）；
- **把图从条上拖出去 → 永久放回**（`onTimerCB` 里的位移判定 → `setHidden(false)`）。

缺口：

1. **没有"点一下就放回"**。放回只有两条路：工具栏那枚隐藏按钮再点一次（可窗口已经不见了，够不着），或"hover 出来再拖出去"——**手感要求很高**，且拖着拖着容易被 800ms 定时器收回去。
2. **看不出哪一格是哪张**。每格只有 4 逻辑像素厚、颜色来自 8 色轮转（`barColors`，按**创建顺序**取，`getBarColorIndex`）。图一多就只能靠 hover 逐张"整窗闪"去认——**屏上有大图时整屏闪**，非常吵。
3. **没有右键**。不存在任何上下文入口（全仓库没有贴图菜单；`SelectPopup` 是工具条下拉专用，`Tray.cpp` 的菜单挂在托盘上）。

## 3. 主张：把「双击」接到书签条，把「书签格」做成一级入口

一句话：**别再新增"第 5 种收起形态"，而是把已有的"隐藏 ↔ 显示"这一对补上顺手的双向交互，并让书签格自己"看得见内容"。**

### 3.1 双击 = 收起 / 放回（统一手势）

> ⚠️ **本节已按作者裁决作废**（裁决：双击保持"复制并关闭"）。保留原文仅供追溯。

| 场景              | 现在的双击                | 提案的双击                         |
| --------------- | -------------------- | ----------------------------- |
| 贴图本体（正常态）       | 复制合图进剪贴板 + **关窗**    | **收起进书签条**（`setHidden(true)`） |
| 书签条上 peek 出来的那张 | —（peek 态本来就没接双击）     | **放回原位**（`setHidden(false)`）  |
| 缩略图             | 图上点一下已还原（double 无意义） | 不变                            |
| 选文态 / 折线续画      | 选词 / 收尾              | **不变**（优先级更高，见 3.4）           |

**"复制并关闭"往哪去**：迁移到 **`Ctrl+双击`**（与 `Ctrl+C` 同族，好记），并在新的右键菜单里保留「复制并关闭」。  
理由：`Ctrl+C` + 关窗这类**破坏性、不可见**的动作绑在裸双击上，误触代价高（想轻轻点两下看看，结果复制走了还关了窗）；而"收起一下"这种**可逆、轻量**的动作才配双击。这与 Snipaste 的直觉一致。

### 3.2 书签格：三级交互（这是"结合"的核心）

| 手势        | 现状                | 提案                                         | 备注                          |
| --------- | ----------------- | ------------------------------------------ | --------------------------- |
| **hover** | 整窗 peek（`reveal`） | **先浮缩略图预览**（安静）；鼠标移入预览 / 停 ~150ms 才整窗 peek | 保留原 peek 手感，只是加了一层"先看小图"的缓冲 |
| **单击**    | 无                 | **放回桌面**（`setHidden(false)`）+ 落到原位         | 补上缺口 ①                      |
| **右键**    | 无                 | **上下文菜单**（见 3.5）                           | 补上缺口 ③                      |
| **拖动**    | 拖出 = 放回           | **不变**（保留；落点即新原位）                          | 老手感不丢                       |



> 关键字：**hover 预览是"读"，单击是"放"，拖动是"搬"** —— 三种意图三种手势，互不抢。

### 3.3 缩略图 hover 预览浮层（补缺口 ②）

> ⚠️ **本节已按作者裁决作废**（裁决：书签 hover 保持"即整窗 peek"）。保留原文仅供追溯。

- 形态：≤240×180 的小窗（等比缩，短边不留白），圆角 + 淡投影，右下角一小行 `尺寸 · 标题`（无标题就只显尺寸）。
- **不抢焦点、不可交互**（`WS_EX_NOACTIVATE` + `WS_EX_TOOLWINDOW`，与 `ToolPinSide` 同款）；鼠标移进去才触发整窗 peek —— 于是"只是想看看是哪张"全程安静，不会整屏闪。
- 与"缩略图形态"（`setThumbMode`）的关系：**一个是收起来的"形"，一个是藏起来后的"识"**，别混。命名上建议叫 `PinHoverPreview`，避免和 `isThumb` 撞车。

### 3.4 双击的优先级（照抄现有顺序，只在末尾插一刀）

`WinPin::onDown` 里现有判定顺序（必须保持）：

```
选文态双击(选词)  →  折线续画双击(收尾)  →  缩略图(点=还原)  →  [新增] 双击收起/放回  →  原有 copyToClipboard
                                                        ↑ 只在 !editingShape && !canvasSelecting() 时才认
```

- `「选择画布」`下不认（与现在排除 `copyToClipboard` 同一条理由）。
- `isLocked` 的贴图：**收起/放回要放开**（这是"把它收起来"不是"改这张图"，与右键收工具条放开的理由同源，见 `onDown` 的 `isLocked && !isRight` 那条）。

### 3.5 右键菜单（补缺口 ③）

**贴图本体右键**现在=切换工具条显隐（保留，右键菜单另找入口——见下）。  
**书签格右键**（新增，菜单落在书签条旁）：

| 菜单项            | 动作                         |
| -------------- | -------------------------- |
| 放回桌面           | `setHidden(false)`         |
| 复制（合图进剪贴板，不关窗） | `copyImageToClipboard()`   |
| 另存为…           | `saveToFile()`（注意它会关窗，放最后） |
| 编辑标题…          | 聚焦 ToolSub 的标题框            |
| 加入分组 ▸         | 见 3.6                      |
| 关闭             | 关窗                         |

**贴图本体右键**的取舍：它现在被"收放工具条"占着（`onDown` 里那段）。两个方案：

- **A（推荐）**：右键仍切工具条；上下文菜单挂在 **`Ctrl+右键`** 或工具条那枚「…」上——不破坏既有肌肉记忆。
- **B**：右键改为弹菜单，把"收工具条"改到 `空格`（空格本来就是收放，且已实现 `setToolsVisible`）。**但空格语义已被占用**（编辑↔拖图硬切换），会变复杂 ⇒ 不推荐。

### 3.6 分组深化（补 gap：现在只有 `toggleGroupAll()` 全有/全无）

- **编组**：`Ctrl+点选`多张 → 右键 → 「编成一组」。保留原全局 `toggleGroupAll()` 作为快捷（不改）。
- **解组 / 移出**：组内任一张右键 → 「移出分组」「解散本组」。
- **与隐藏联动**（关键结合点）：**单张仍是单张书签格，不把一组并成一格**（一格代表一组会引入"这一格点下去放谁"的歧义）。但组内右键菜单加两项：「整组收进书签条」「整组放回」。
- 组语义保持现有：成组后拖动 / Ctrl+滚轮同步（`syncGroupPos` / `syncScale`）。

## 4. 与既有实现的衔接点（实施清单）

| 要做的事                          | 落在哪                                                                        | 注意                                                                               |                                            |
| ----------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------ |
| 双击收起/放回                       | `WinPin::onDown` 双判定处（`isDblClick && !editingShape && !canvasSelecting()`） | 插在 `copyToClipboard()` **之前**；`Ctrl+双击` 才走原逻辑                                    |                                            |
| 调出 `takeDoubleClick` 的 Ctrl 态 | 同处                                                                         | `onKey`/`onDown` 里已有 `ctrlUsedAsModifier` 语义可借，**别再新引入一个时间阈值**                   |                                            |
| 书签格单击=放回                      | `PinHiddenBar`：给 `bars[i]` 节点挂 `onClick`                                   | 现在只挂了 `body->onMouseMove`；`onClick` 要新挂（并在 rebuild 时随子节点重建）                      |                                            |
| 书签格右键                         | `PinHiddenBar`                                                             | 建议复用系统 `CreatePopupMenu` + `TrackPopupMenu`（与 `Tray.cpp:69` 同一套），别自绘             |                                            |
| hover 预览浮层                    | 新 `PinHoverPreview`（照 `ToolPinSide` 的窗口骨架）                                 | \`WS_EX_NOACTIVATE                                                               | TOOLWINDOW`；`reveal`里先弹预览、延时再`peek(true)\` |
| 「整组」菜单项                       | `WinPin::setHidden` 批量版                                                    | 需要"整组藏"入口：遍历 `groupId` 相同的成员逐个 `setHidden(true, edge)`，`PinHiddenBar::sync()` 一次 |                                            |

> ⚠️ 三个已知的坑直接抄结论（详见 `.workbuddy/memory/RUNBOOK-gui-repro.md` / `MEMORY.md`）：  
> ① `WinPin::saveToFile()` 保存成功会 `close()` 关窗 ⇒ 菜单里它必须排最后；  
> ② `createNativeWindow` 建的窗口**不带 `WS_VISIBLE`** ⇒ 预览浮层 `init` 里必须自己 `show()`（漏了症状是"第一次点没反应、第二次才出来"）；  
> ③ `PinHiddenBar::rebuild` 会 `body->removeAllChildren()` ⇒ 新挂的 `onClick` / 右键必须**在 rebuild 里重新挂**，挂一次会被清掉。

## 5. 作者裁决（2026-10-09）与据此收敛后的范围

| 议题        | 裁决                 | 对本设计的影响                                                                                  |
| --------- | ------------------ | ---------------------------------------------------------------------------------------- |
| 双击语义      | **保持"复制并关闭"**      | §3.1 **整段作废** —— 不做双击收起/放回，也不引入 `Ctrl+双击`                                                |
| 书签条 hover | **保持"即整窗 peek"**   | §3.3 **整段作废** —— 不做缩略图预览浮层；"哪格是哪张"仍靠 peek 辨认                                             |
| 分组        | **改成 `Ctrl` 多选编组** | §3.6 落实为"`Ctrl` 多选 → 右键编成一组"                                                             |
| 本体右键      | **改成弹上下文菜单**       | §3.5 落实；**"收放工具条"改由 `空格` 承担**（它本就是 `setToolsVisible`），菜单里保留「显示/隐藏工具条」一项——锁定态下右键是唯一入口，不能断 |

> 于是 §3.2 维持**三种手势**：hover（peek）/ 单击（放回）/ 右键（菜单）；拖动（放回）保留。

### 6.1 右键菜单内容定稿

**贴图本体右键**（`WinPin::onDown` 的 `if (isRight)` 分支）：

```
复制到剪贴板      copyImageToClipboard()   （不关窗）
复制并关闭        copyToClipboard()        （沿用双击语义，菜单里也留一份）
另存为…           saveToFile()             （成功会关窗 ⇒ 排最后）
--------------------
隐藏到书签条      setHidden(true)
缩略图 / 恢复大小  setThumbMode(!isThumb)
贴边细条 / 展开     setMinimized(!isMinimized)
显示 / 隐藏工具条   setToolsVisible(!isToolsVisible())   （锁定态的唯一找回入口）
--------------------
加入分组 ▸ / 移出分组 / 解散本组          （§3.6）
整组收进书签条 / 整组放回
--------------------
关闭              close()
```

**书签格右键**（`PinHiddenBar`）：`放回桌面 / 复制到剪贴板 / 另存为… / 整组放回 / 关闭`。

### 6.2 分组手势定稿（避开既有 Ctrl 语义）

- 触发条件：**手里没有画笔（`!hasDrawTool()`）+ 按住 `Ctrl` + 左键单击**（按下与抬起之间没移动，靠 `hasDragged` 判）。
  - 为什么不冲突：有画笔时 `Ctrl+单击` 是"画布对象加减选"；**没有画笔时**左键本就归"拖窗口"分支（`onDown` 空白三态），此刻 `Ctrl+单击` 是空的 —— 正好拿来当"选这一张贴图"。
- 选中态视觉：该贴图窗口画一圈高亮边框（与现有蓝色边框区分）。
- 选中 ≥2 张后，右键任一选中贴图 → 菜单出现「编成一组」；选中 0/1 张时菜单显示的是普通组项。
- 点空白 / `ESC` 清空"待编组选中"。
