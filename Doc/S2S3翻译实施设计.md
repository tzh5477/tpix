## 1. 能力目标

| 需求 | 实现 |
|---|---|
| 对接火山引擎翻译接口、支持输入 API key | `AiTranslate` 的 volc 分支，自签名 v4 |
| 或对接大模型实现翻译 | `AiTranslate` 的 model 分支，复用 `AiService::chat` |
| 翻译参考 pot-desktop | 取词路径走 **「截图 → OCR → 翻译」**，见 §3 |

为什么取词走 OCR 而不是全局划词：pot-desktop 的划词翻译靠「模拟 `Ctrl+C` 抓选中文字」，
那套在浏览器里经常取不到东西（不少页面会先取消选区）。tpix 自己有内置离线 OCR，
**文字本来就在手上**，直接送翻译窗，既可靠又不侵入别的程序。

## 2. 服务层：`Src/AiTranslate.h/.cpp`

### 2.1 两条路

| 分支 | `ai.transProvider` | 凭据 | 请求 |
|---|---|---|---|
| 火山 | `volc`（默认） | `ai.volcAk` / `ai.volcSk` | `POST https://translate.volcengineapi.com/?Action=TranslateText&Version=2020-06-01` |
| 大模型 | `model` | 复用 `ai.baseUrl` / `ai.apiKey` / `ai.model` | 复用 `AiService::chat`（流式） |

对外只有一个入口 `AiTranslate::run(text, from, to, onDone)`，返回 `AiService::TaskPtr`
（取消语义与对话共用：**取消也会回调 onDone**）。调用方不需要知道走的是哪条路。

### 2.2 火山签名 v4（三处最容易写错，已按官方文档逐条确认）

参考 `https://www.volcengine.com/docs/4640/66284` 与官方 Python 样例
（`https://www.volcengine.com/docs/ndb_for_mysql/1390583`）。

1. **CanonicalQueryString 要带上 `Action=TranslateText&Version=2020-06-01`**。
   请求就是打在带查询串的那个地址上，省掉它签名必然对不上；
2. **CanonicalHeaders 每个条目自带 `\n`，规范在它与 SignedHeaders 之间还有一个 `\n`**
   —— 那里是一个**空行**，不是笔误；
3. 派生密钥的最后一步常量是 **`request`**（不是 AWS 的 `aws4_request`）。

```
CanonicalRequest = POST \n / \n Action=…&Version=… \n
                   content-type:application/json \n
                   host:translate.volcengineapi.com \n
                   x-content-sha256:<hex> \n
                   x-date:<YYYYMMDDTHHMMSSZ> \n
                   \n
                   content-type;host;x-content-sha256;x-date \n
                   <hex>
```

其余细节：

- **时间戳只取一次**：签名串与 `X-Date` 头必须是同一个值，取两次可能跨秒；
- **十六进制自己转小写**，不用 `CryptographicBuffer::EncodeToHexString`（它的大小写不该被指望，
  而签名要求小写）；
- **`Content-Type` 显式设成 `application/json`**：签名里写的是这个值，
  若 `HttpStringContent` 自己补上 `; charset=utf-8`，签名就对不上了；
- 加密全走 WinRT `Windows.Security.Cryptography.Core`（`HashAlgorithmProvider` /
  `MacAlgorithmProvider` + `CryptographicEngine::Sign`），**用的是已链的 `windowsapp.lib`，不新增依赖**。

### 2.3 请求体与响应

```jsonc
// 请求。不带 SourceLanguage 就等于让它自己检测
{ "SourceLanguage": "zh", "TargetLanguage": "en", "TextList": ["…"] }

// 成功
{ "TranslationList": [{ "Translation": "…", "DetectedSourceLanguage": "zh" }], "ResponseMetadata": { … } }
// 业务错误：HTTP 仍是 200，错误在 ResponseMetadata.Error.{Code,Message}
```

**分片**：火山限制 `TextList` ≤ 16 项、总文本 ≤ 5000 字符。整页 OCR 很容易超，
所以 `splitParts()` 按行切成若干段一起发；切完还超才报错，**绝不悄悄截断**。
（已知边界：单行超过 4500 字符时不会硬切，那种情况由服务端报错回来。）

**错误码** `-400 参数错 / -415 不支持的语向 / -429 太频繁 / -500 服务内部错`，
`Code + Message` 一起显示给用户 —— 415 与 401 的处理办法完全不同，用户得能分清。

### 2.4 大模型那条路

只换提示词，其余复用对话：

- system：`你是专业翻译引擎。只输出译文本身，不要解释、不要加引号、不要重复原文。`
- user：`请把下面这段内容翻译成<目标语言名>：\n<原文>`（指定了源语言时前面再加一句）

**用语言名而不是语言代码**（`zh` → `中文`）：模型对名字更稳。语言名走语言包
`ai.lang.<code>`，界面语言换了名字也跟着换。

## 3. 取词翻译的路径

```
截图 → WinOcr（内置离线 OCR 认字）→ 点「翻译」
     → WinAiTrans::init(识别出的文字) → 自动翻一次 → 出译文
```

托盘右键菜单「翻译」打开的是同一个窗，只是不带预设文字（手动输入）。

`WinOcr` 底部新增的「翻译」按钮就是这条路的入口。它不新起识别：
`result` 已经是当前显示的文字，拿去就用。

## 4. 翻译窗 `Src/Win/WinAiTrans.*`

- 语言行：**源语言 ▾ / ⇄ / 目标语言 ▾**。目标语言的下拉**没有「自动检测」这一项**
  （火山要求 `TargetLanguage` 必填，而"译成自动检测"没有意义）；
  源语言是「自动检测」时点交换不动 —— 同样因为它不是一种语言。
- 上文本框 = 原文，下滚动区 = 译文，下面两个按钮 = 翻译 / 复制译文，
  状态行显示「正在翻译…」「检测到：XX」或错误。
- **翻译中再点按钮 = 取消**（按钮文案切成 `ai.stop`）。
- 语言选择落盘到 `ai.transFrom` / `ai.transTo`，下次开窗沿用。
- 送去之前先裁掉首尾空白：OCR 出来的文字常常带一堆换行，全送去翻是白花钱。
