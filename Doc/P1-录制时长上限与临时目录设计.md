# P1 录制时长上限与录制临时目录 · 设计（2026-10-10）

> 对应作者原话：
> 「1、录屏操作我希望新增一个设置录制时间限制及倒计时显示的功能，仅用户界面可见倒计时，
> 录制结果视频不展示倒计时；场景：应标材料中需要提供不超过 5 分钟的视频。
> 2、目前录屏限制了最长时间为 120 分钟，GIF 才 6 分钟，建议取消限制，用户甚至有录制一天视频的场景。」

## 0. 结论摘要

| 项 | 决定 |
| --- | --- |
| 时长上限 | **默认 120 分钟**（= 老版本 MP4 的硬编码上限，老用户升上来行为不变），可自由输入，**0 = 不限时** |
| 录制中改上限 | 点工具条上的计时格弹小窗改，改完**下一个 tick 就生效**，不必停录 |
| 倒计时形态 | 有上限显示 `剩余 mm:ss`，**最后 30 秒变主题色**；不限时显示**已录时长**（纯秒表，无前缀） |
| 到点行为 | 自动停录 → 直接弹保存框（复用 `ToolVideo::saveFile()`） |
| 倒计时可见性 | **只在工具条上**。工具条整体挂了 `WDA_EXCLUDEFROMCAPTURE` ⇒ 不会录进视频 |
| 落盘位置 | 新增「录制临时目录」设置，默认仍为空（= 数据目录 `%appdata%\tpix`），可指到大分区 |
| GIF | 上限与 MP4 **统一读同一个配置**（原来写死 6 分钟）。见 §8.2 —— "取消限制"对 GIF 不能照字面兑现 |
| 不做 | 分段录制、到达上限后自动分卷、按剩余时间动态降码率 |

## 1. 现状（改动前）

```
ToolVideo::showRecording()   timerLabel(Label) 显示 "{elapsed} / {max}:00"
ToolVideo::updateTimerText() maxMinutes = (selectIndex == 1) ? 6 : 120     ← 硬编码
ToolVideo::onTimerCB()       totalSeconds += 1; if (totalSeconds >= maxSeconds) saveFile();
CapVideo::startMp4()         videoTempPath = Setting::get()->getDataPath()  ← 落点写死
CapVideo::startGif()         同上
WinVideoEdit::exportAs()     tmpOut = Setting::get()->getDataPath().append(L"trim.mp4")
```

三个前提事实（决定了做法）：

1. **上限只在 UI 层**：编码器（`VideoMp4` / `VideoGif`）里没有任何时长上限，`onTimerCB` 那个
   计数是唯一的闸门 ⇒ 改上限不需要动编码链路。
2. `Ling::Label` **没有 onClick** ⇒ 计时格要可点，必须换成 `Ling::Button`。
3. 工具条是 `WDA_EXCLUDEFROMCAPTURE` 的（`CapVideo.cpp:136`）⇒ 放在上面的倒计时天然不会被录进视频，
   不需要额外做"录制时隐藏 UI"。

## 2. 范围与裁决（作者已定）

| 问题 | 裁决 |
| --- | --- |
| 上限范围 | 默认 120 分钟，支持自由输入，**且支持在录制时间结束前修改上限** |
| 倒计时形态 | 设了上限显示「剩余 mm:ss」，最后 30 秒变主题色；不限时显示已录时长 |
| 到点行为 | 自动停止 → 直接弹保存框 |
| 落盘位置 | 新增「录制临时目录」设置，默认仍为 `%APPDATA%`，可指到大分区 |

## 3. 数据模型

新增 config.json 顶层组 `video`（`Setting::getVideoObj()`，缺则现建）：

| 键 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `video.timeLimitMin` | number | `120` | 录制时长上限，**分钟**，`0` = 不限 |
| `video.tempDir` | string | `""` | 录制临时文件落点；空串 = 数据目录 |

- 读取时夹到 `[0, 100000]`。**100000 分钟（约 69 天）只是防溢出的哨兵，不是产品限制** ——
  需求就是"取消限制"，这个上界远超出任何真实录制时长。
- `Setting::parseTimeLimitText(text)`（**静态**）把输入框那串字解析成分钟数，返回 `-1` 表示
  "一个数字都没有"。设置页的输入框与录制中改上限的小窗**共用这一份** —— 两边对"什么算有效输入"
  必须给出同一个答案，否则同一个数字在设置页存进去是 120、在小窗里存进去变成 0。
  非数字字符（`"120 分钟"`）直接跳过而不是判错；`0` 是合法值，所以不能拿 0 当失败标记。
- `Setting::getRecordTempDir()` 返回 `std::filesystem::path` **副本**（调用方还要 `append` 文件名），
  配的目录建不出来时**静默回落**数据目录 —— 弹框拦住录制不划算，录到的文件在哪用户一看就知道。

## 4. UI 与交互

### 4.1 设置页（`WinSettingCommon::initVideoCtrls()`）

排在「滚动截图方向」之后、「保存格式」之前：

```
录制时长上限：  [ 120 ] 分钟  0 = 不限时
录制临时目录：  [ 未设置（用数据目录） ]
```

- 上限框是 `Ling::TextBox`（96×28 逻辑像素）。**落盘时机是"离开输入框 / 回车"，不是每次按键**：
  逐字落盘的话，把 120 改成 30 的中途会先存下 1、12，而 1 分钟意味着录制一秒后就自动停止 ——
  那是真的会丢内容。敲了串非数字则回显原值、不改配置。
- 临时目录按钮复用 `WinSettingCommon.cpp:17` 的 `pickFolder()`（`IFileDialog` + `FOS_PICKFOLDERS`），
  跟「保存目录」那一行完全同款。

### 4.2 录制中的工具条

计时那一格由 `Label` 换成 `Button`：

| 状态 | 显示 | 颜色 |
| --- | --- | --- |
| 设了上限，剩余 > 30s | `剩余 mm:ss` | `0x333333` |
| 设了上限，剩余 ≤ 30s | `剩余 mm:ss` | **主题色**（`Setting::getThemeColor()`） |
| 上限 = 0（不限时） | `mm:ss`（已录时长） | `0x333333` |

- 用**变色**而不是闪烁：工具条是置顶小窗，用户眼睛多半在别处，"变色"更容易被余光抓到，
  也更好截图取证。
- 点这一格弹「改上限」小窗；悬停给 `Tip` 提示「点击修改录制时长上限」。
- 超 1 小时才带小时位（`fmtDur`）：上限可到 100000 分钟，位数不能写死成两位分钟
  （"录一天"时那是 `1440:00`）。

### 4.3 「改上限」小窗（`WinRecordLimit`）

300×164 逻辑像素的无边框置顶小窗，贴在工具条**上方**（上方放不下就翻到下方，并夹进工作区）：

```
录制时长上限
输入分钟数，0 表示不限时
[ 1        ] 分钟
[不限]            [取消] [确定]
```

- **预填当前值而不是用占位符**：占位符是灰的，看着像"这里现在是空的、不填就是不限时"，
  而这恰好是最需要说清的一处（不填其实是"不改"）。预填 + `selectAll()`，想改就直接打。
- 回车 = 确定，ESC = 取消。**必须挂在 `TextBox::onKeyDown` 上并把 `*handled` 置真** ——
  `TextBox` 自己只认 `VK_RETURN` 一律换行、`VK_ESCAPE` 一律失焦，窗口级事件抢不过它的默认行为。
- 窗口自带 `App::excludeFromCapture()`：它会盖在录制画面上，不能录进去。

## 5. 关键实现决定（后人别改）

1. **`WinRecordLimit` 不持有 `ToolVideo*`，而是现问 `ToolVideo::living()`。**
   工具条随时可能被销毁 —— 典型就是"倒计时到点自动停止"那一刻，而那正是小窗最可能开着的时刻。
   存指针就是悬垂。`liveTool` 在 `onCreated` 登记、`onDestroy` 注销（顺手 `closeIfOpen()` 收掉小窗）。
2. **上限每个 tick 现读，不缓存。** `updateTimerText()` / `onTimerCB()` 都现调
   `Setting::get()->getVideoTimeLimitMin()`，这样"设置页改了""录制中改上限"下一拍就跟着变，
   不需要任何通知机制。`onLimitChanged()` 只是为了让用户"改完马上看见"，调不调都对。
3. **暂停时不计数但仍刷文字**：暂停着改了上限，倒计时得马上变。
4. **`timerBtn` 必须配 `setHoverBg`**：`Button` 设了 `setBg` 就必须设 `setHoverBg`，
   否则一悬停画刷会被换成没建过的空刷，整块变空白（Ling 的硬规矩）。
5. **落点是"录制临时目录"，不是"保存目录"**：裁剪产物（`trim.mp4`）跟源片同一份目录 ——
   它和源片是一个量级，就该和源片待在同一块盘上。默认仍是数据目录，没配过的话行为与以前完全一致。

## 7. 踩坑清单（都已在代码注释里标了原因）

1. **成员函数 `show` 遮蔽基类 `show`** —— `WinRecordLimit` 有个静态 `show(HWND,float)`，
   成员函数里写 `show()` 会解析到那个静态版本，报 C2660。必须写 `Ling::WinBase::show();`。
2. **`std::make_unique` 不是私有构造函数的友元** —— C2248。照 `WinTextPin` / `WinDelay` 那样
   `std::unique_ptr<T>(new T(...))`。
3. **`createNativeWindow` 不带 `WS_VISIBLE`** —— 不自己 `show()` 就是"第一次点没反应、第二次才有窗口"。
4. **单行 `TextBox` 的常驻滚动条** —— `TextBox` 构造默认上下各 6 的 padding，28 高的框只剩 16 逻辑像素
   装文本，而一行 14 号字就有 ~19 ⇒ 内容永远"溢出"半行，滚动条常驻、顺带把基线以下那截（`_`、`y` 的尾巴）
   裁掉。解法是 `setPadding(6.f, 0.f, 6.f, 0.f)`（让位给 `setVerticalCenter`）。
   `WinSettingAi.cpp:306` 早就写下了这条注释并覆盖了六个框，**「文件名模板」那只是漏网的**。
5. **`probe` 用 `PostMessage` 顶托盘菜单 ⇒ tpix 从没成为前台进程** ⇒ 新建的 `WinSetting` 落在
   前台窗口之下，"窗口存在、`cloaked=0`、`vis=True`，但截图上什么都没有"。
   这是**工装问题不是产品缺陷**，探针里加一句 `SetWindowPos(HWND_TOPMOST)` 即可见。
6. **菜单项位置别用像素公式猜** —— "第 N 项中心 = 16 + (N-1)*26 + 分隔线*11" 这套经验公式把
   「设置」算成了「十字准线」（点出来一个放大镜）。改用 `MN_GETHMENU` + `GetMenuItemRect`
   现问菜单 API，再**点击前先悬停截图确认高亮的是哪一项**。
7. **改上限小窗截不到图** —— 它自己挂了 `WDA_EXCLUDEFROMCAPTURE`（这是刻意的），
   `ImageGrab` 拍不到，`PrintWindow` 也是空白，`SetWindowDisplayAffinity(WDA_NONE)` 跨进程被拒
   （`ERROR_ACCESS_DENIED`）。要拍画面只能用旁路构建。

### 8.2 🔴 遗留：GIF 那条路没有实测，"取消限制"对它不能照字面兑现

- 代码上 GIF 已经和 MP4 一样读 `video.timeLimitMin`（`selectIndex == 1 ? 6 : 120` 那处硬编码已删），
  所以"上限可配 / 可改 / 到点自动停"这三条对 GIF 一并成立。
- **但 GIF 走 gifski，帧是全缓存在内存里的**（MP4 是边采边写盘）。1 分钟 GIF 就是几百 MB 内存量级，
  "录一天"的 GIF 是不可行的 —— 不是上限拦着，是编码路径本身撑不住。
  ⇒ 需要的话，GIF 应该单独给一个"内存/体积能承受"的上限并如实提示，而不是跟着 MP4 一起放开。
- 本轮没有实测 GIF 路径（验收以 MP4 为主）。
