# tpix 竞品对比刷新分析（含 Snipaste，2026-Q4）

> 对比对象：**tpix**（本仓库现状）· **PixPin**（3.5.x，免费+会员）· **FastStone Capture / FSCapture**（11.2，商业授权）· **Snipaste**（2.11.x，免费）
> 口径：✓ 已实现／△ 部分或较弱／✗ 无。tpix 侧结论均经本仓库源码核对（`Src/`），非 ReadMe 宣传口径。

## 0. 为什么写这篇（刷新说明）

旧文档 `Doc/竞品能力差距分析.md` 写于实施前（约 2026-10-01），本质是一份**路线图**，里面大量"tpix 缺失 X"的论断如今已经做完。经源码核对：

- `WinPin` 已从单例改为**多实例**（`std::vector<WinPin*>` + `getHiddenPins`）；
- `WinBall` / `WinHistory` / `ShotHistory` / `PinSource` / `SelectPopup` / `ShapeWatermark` / `WinOcr` / `WinOverlay` / `GlobalMouse` / `Table` 等全部已在仓库落地；
- `Util.cpp` 的 `ImgFormat` 枚举为 `Png/Jpeg/WebP` + `autoSavePath` + `nameTpl`，即 A5 输出格式与自动保存已落地（**PDF/AVIF 尚未做**）。

此外，旧文档**完全未覆盖 Snipaste**——而 Snipaste 是"贴图"这一品类的开创者、PixPin 的产品源头，其贴图交互成熟度与"离线零上传"形象是独立维度。本篇把现状按源码重新判定，并补齐 Snipaste。

> **成稿后已跟进的 P0 三项**（本篇里"尚未做"的论断以这几条为准）：
> **PDF 导出**（`Util::ImgFormat::Pdf`，零依赖手写最小 PDF 1.4 编码器，见 `encodePdfBytes`）、
> **画笔 / 荧光笔**（`ShapeBrush`，单类 + `highlighter` 标志）与线条工具第三档 **折线**（`ShapeLine::Kind::Polyline`，点选式）、
> **窗口内 `,` / `.` 翻历史截图**（`WinPin::previewHistory` 的新键位）。

## 1. 定位与口径

- **tpix 当前定位**（来自旧文档用户裁决，已执行）：对标 PixPin，引入**云端 AI**（D4 翻译 + 对话）；体积不再是约束条件。
- **明确不做**（与定位冲突，已裁决）：FSCapture 编辑器方向（F 组）、公式识别（D3）、macOS、UI 元素级检测（E1）、深色模式/脚本 API（H2/H4）、录后视频编辑（G3）、GPU 视频编码（G4）。
- **独有优势（应守住）**：本地内嵌二维码识别（quirc）、标注元素实时二次编辑、`--auto-quit` 脚本化流水线、剪贴板三格式兼容（CF_DIBV5/CF_DIB/PNG）、自研可控上游 Ling。

## 4. 剩余的真实差距（按竞品分）

### 4.1 相对 PixPin（同车道内的差距）
1. **画笔 / 荧光笔 / 折线 / 聚光灯**（H6 剩余项）——tpix 标注集里最显眼的空缺，批注类场景刚需。
2. **摄像头画中画**（G1 剩余）——PixPin/FSCapture 均有，需独立 MF 摄像头采集管线。
3. **录后轻量视频编辑**（G3 剩余）——PixPin 有剪切/缩放标注，tpix 无。
4. **PDF 导出未做**——PixPin 有，tpix 现仅 Png/Jpeg/Webp。
5. **贴图交互成熟度**——PixPin 右键菜单（文本识别/图像处理/缩略图/锁定）比 tpix C 组框架更细。
6. **动作录制的精细度**——tpix G2 已有基础，PixPin 的"动作录制"更产品化。

### 4.2 相对 FSCapture（有意不做，但属真实差距）
1. **整条图片编辑器**：裁剪/旋转画布、锐化、亮度色彩、阴影/边框/撕裂边/渐变边、多标签多工作区——tpix 为 0 覆盖（F 组已裁决不做）。
2. **输出格式与目的地**：PDF/FSC 工程格式、打印/邮件/OneNote/Word/Excel/PPT/FTP——tpix 缺整组。
3. **多级菜单捕获**、**摄像头**、**触摸界面**——FSCapture 的桌面工具深度。

### 4.3 相对 Snipaste（贴图鼻祖的维度）
1. **历史回放快捷键（`/` `.`）**——快速重拍上次区域，tpix 有历史面板但缺键盘快回放。
2. **主题色 / 界面字体 / 通知栏图标自定义**——Snipaste 强调的"可定制外观"，tpix 暂无。
3. **HTML/富文本转图片**——Snipaste 把剪贴板 HTML 渲染成图，tpix C1 仅文本/颜色。
4. **批量 OCR 多图**——一次性识别多张截图，tpix 仅单图。
5. **跨平台（macOS）**——Snipaste 双平台，tpix 单平台（独立工程，已裁决）。
6. **离线零上传形象**——Snipaste 立身之本；tpix 已走云端 AI，属**定位分歧**而非功能缺口。

## 5. 值得借鉴的功能（优先级 + 理由 + 与定位契合度）

### P0 — 在 tpix 自身车道内、成本低收益高

| 功能 | 借鉴自 | 理由 | 契合度 |
| --- | --- | --- | --- |
| **画笔 + 荧光笔**（H6 剩余前两） | PixPin | 批注场景最刚需的两种笔；纯本地、无外部依赖、落在已理顺的 A1 容器上 | 高（正是 PixPin 主干体验） |
| **历史回放快捷键（`,`/`.`）** | Snipaste | tpix 已有历史面板(B2)，补键盘快速重拍上次区域，工作量极小、感知强 | 高 |
| **PDF 导出** | FSCapture/PixPin | 文档场景高频；WIC 不支持 PDF，需另引轻量写库（如 libharu/打印后台），中等成本 | 中高（tpix 现仅三格式） |

| 功能 | 借鉴自 | 理由 | 契合度 |
| --- | --- | --- | --- |
| **贴图交互打磨**（缩略图 hover 预览、双击隐藏/显示、分组右键深化） | Snipaste | C 组已搭框架，补交互细节即可，是"贴图工具"质感的来源 | 高 |

| **录后轻量视频编辑**（G3 剩余） | PixPin | 剪切/缩放标注，中等投入 | 中 |

### P2 — 长尾/锦上添花

| 功能 | 借鉴自 | 理由 |
| --- | --- | --- |
| **HTML/富文本转图片** | Snipaste | 需 HTML 渲染，成本高，非主干 |

## 6. 不建议照搬（定位冲突，需主动取舍）

- **FSCapture 整条编辑器 + 多目的地（打印/Office/FTP/邮件）+ FSC 工程格式**：用户已裁决 F 组不做，且与"对标 PixPin"主线不符。tpix 应守住"截图 → 贴图 → AI"而非变成图像编辑工作站。
- **严格离线零上传（Snipaste 立身之本）**：tpix 已选云端 AI 路线，不必、也不应回退；但应**保持 OCR 本地**（已做到 `Windows.Media.Ocr`）+ 明确告知 AI 模块需联网，守住隐私叙事。
- **macOS 版**：独立工程（Ling/DXGI/MediaFoundation 全 Windows 专属），单独立项。
- **公式识别**：模型 100MB+，受众极窄，已裁决不做。

## 7. 一句话结论

tpix 在"**贴图体系 + 本地 OCR + 标注二次编辑 + 云端 AI**"这条自己选定的车道上，相对 PixPin 的差距已大幅收敛；剩余最该补的是**批注工具的最后两块拼图（画笔/荧光笔）、历史回放的键盘快捷、以及 PDF 导出**。相对 FSCapture 的"编辑器 + 多目的地"是有意不做而非落后；相对 Snipaste 则应借鉴其**贴图交互的成熟度与可定制外观**，而非其离线洁癖。

> 旧文档 `竞品能力差距分析.md` 中"tpix 缺失贴图层 / 输出入口过窄 / 历史截图"等结构性论断，已随 A/B/C 组实施而**关闭**；仅"无图片编辑器"这一条仍为真（且为有意）。本篇取代其"差距现状"部分，路线图部分仍可作历史参考。
